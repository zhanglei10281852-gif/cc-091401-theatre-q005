# 巡演物流服务

追踪戏剧巡演多城转场的箱体、封签、装载、换车与异地交接。上海 → 西安 → 成都示例见 `reference/`，完整事故场景可运行 `npm run demo` 复现。

## 领域规则

- **装卸顺序**：后卸先装（LIFO）。默认灯具/索具先卸（装台最先用），可按段自定义卸货序号；序号 N 对应下一站卸货位 `<City>-DOCK-NN`。
- **危险品**：烟火制品(1.4G) 与加压喷雾(2.1)、锂电池(第 9 类) 相斥，不得同舱；危险品只能装入 `hazardCapable` 舱位。
- **超重/超尺寸**：逐舱校验载重、边长与容积；整车超载给出总重、上限与超出数值。
- **时间窗**：逐城推演「进站（早到等待）→ 卸/转舱/装 → 离站 → 行驶」链；压缩装台窗口时返回晚到分钟数等具体原因。
- **换车**：优先沿用上段车辆；中途换车额外计入转舱耗时，计划中固化换车说明。
- **卸货位锁定**：交接一旦开始，其下一站卸货位即被确认；后续重排若抢走该位置，规划直接拒绝。

## 不可变性

所有写操作落为只追加事件（`.runtime/events.jsonl`，JSONL）：

- 封舱清单固化后带 SHA-256 摘要；同段重封生成 `v2/v3…`，历史版本与摘要永不改变。
- 交接以独立 `handover_completed` 事件收尾，历史交接不可覆盖（再次完成返回 `handover_closed`）。
- 破封、暂扣、换箱、拆分只能 `POST /v1/exceptions` 追加例外，每条例外附带对后续各段的影响评估（阻塞段、受影响清单、缺件风险、重新封签要求）。
- 重启即重放事件日志，未完成交接、扫码进度、超时提醒与封签链保持连续。

## 离线扫码

扫描枪离线缓存，网络恢复后整批上传。幂等键为 **设备序列号 + 设备内自增序号**（`deviceId` + `seq`）：

- 重复批次只回 `duplicates`，不产生重复事件；
- 同序号内容不一致（覆盖/伪造）整批拒绝（`seq_conflict`）；
- 支持「先离线扫、后建交接」，扫码按箱体自动归到最早的待办交接。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/cases` | 登记箱体台账（幂等；已登记箱体字段变更被拒，须走换箱/拆分例外） |
| GET  | `/v1/cases/:caseId` | 器材主管扫码查箱：当前责任人、封签链、例外、缺件状态、最近扫码 |
| POST | `/v1/plans` | 按城市窗口 + 车队生成装载/换车计划；不可行返回 422 与具体原因 |
| GET  | `/v1/plans/:planId` | 读取计划 |
| POST | `/v1/manifests` | 固化某段封舱清单（逐箱 `S-######` 封签、舱位、卸货位 + 摘要） |
| GET  | `/v1/manifests/:id` | 读取封舱清单（含摘要与 digest） |
| GET  | `/v1/legs/:legId/manifests` | 某段全部历史版本 |
| POST | `/v1/handovers` | 开始交接（锁定卸货位，占用冲突返回 `slots_locked`） |
| POST | `/v1/handovers/:id/complete` | 扫码核对封签链后签收；缺箱须逐箱登记 shortages |
| POST | `/v1/scans/batch` | 离线扫码批次幂等合并 |
| POST | `/v1/exceptions` | 追加 `broken_seal` / `held` / `swap` / `split` 例外并返回影响评估 |
| POST | `/v1/exceptions/:id/release` | 解除暂扣（追加解除记录，不删除原例外） |
| GET  | `/v1/alerts` | 超时未完成交接 + 缺件/暂扣告警 |

错误约定：`400 validation_failed`（含 `reasons[]`）、`404 not_found`、`409`（业务冲突）、`422 plan_infeasible`（规划不可行，含具体原因）。

## 运行

需要 Node.js 22 或更高版本。

```bash
npm ci
npm test          # 27 个测试
npm run demo      # 上海→西安→成都事故场景演示（临时数据目录）
npm start         # 默认 :8000，事件数据在 .runtime/（可用 LOGISTICS_DATA_DIR 覆盖）
```

也可以使用 `docker compose up --build` 启动容器。
